# Cart Item Validation: High-Level Design (HLD)

For requirements, design decisions and gaps, see [requirements-and-solution-design.md](requirements-and-solution-design.md).

## 1. Systems involved

| System | Role |
| --- | --- |
| ACCS (Commerce) | Owns the carts, sends the webhooks, hosts Commerce Admin and App Management |
| App Builder (Runtime) | Runs the webhook actions and the settings actions |
| App Management business configuration | Stores the three settings at global scope |
| Admin UI SDK | Shows the **Stores > Cart Item Validation** page |

The app adds no custom database and no Commerce PHP code.

## 2. Architecture

```text
Shopper or Admin user changes a cart
        │
        ▼
ACCS webhook (type: before, required: true)
  ├─ add item  ──┐
  ├─ save item ──┴──► validate-cart-item ───┐
  └─ merge cart ─────► revalidate-quote-merge ┤
                                              ├─ 1. read settings (global)
                                              ├─ 2. compare quantity with maximum
                                              ├─ 3. optional correction (Cart REST API)
                                              └─ 4. return success or exception

Admin ─► App Management settings form ─────────────────────────────┐
Admin ─► Stores > Cart Item Validation ─► get/save actions (ACL check) ─┴─► shared global settings
```

## 3. Extension points

| Extension point | Folder | Purpose |
| --- | --- | --- |
| `commerce/extensibility/1` | `src/commerce-extensibility-1/` | Webhook actions and App Management install actions |
| `commerce/configuration/1` | `src/commerce-configuration-1/` | App Management settings form (generated by the SDK) |
| `commerce/backend-ui/2` | `src/commerce-backend-ui-2/` | Custom Admin page and its settings actions |

- `app.commerce.config.ts` declares the settings, the webhooks and the Admin menu.
- Files under `.generated/` belong to the SDK. Never edit them.

## 4. Security

- Every action requires Adobe authentication.
- The settings actions also check the Admin menu permission on the server.
- Credentials stay in the local `.env` and `.aio` files and are never committed.

## 5. Reliability

- If the settings cannot be read, or the payload is malformed, carts are **allowed** and an error is logged.
- Saving settings fails safely: nothing is saved on error.
- Correction reads the cart before writing, tries at most 2 times, then logs `CRITICAL`.
- Webhooks have a 5-second timeout. Because they are `required: true`, an outage blocks the cart with the fallback message "Unable to update the cart right now. Please try again."
- `_after` events may not undo a save, so live testing is needed (gap G-7).
